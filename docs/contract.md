# Holy Hymns API implementation contract

Base `/v1`. JSON lowerCamelCase. Error `{error: string, code?: string}`. Bearer opaque session token. Responses are direct objects; lists use `{items:[], total:number}`. All UUID identifiers are strings. Dates RFC3339.

Song: `{id,title,titleMalayalam,lyricsMalayalam,lyricsManglish,aliases:string[],credits,links:[{label,url}],categoryIds:string[],featured:boolean,version:number,status:'draft'|'published',updatedAt,sourceUrl?,reviewNotes?:string[]}`. title is romanized/display title; at least one lyrics field required on publish, draft can be incomplete. Song create/edit body has these content fields, plus `version` for updates. Published and draft snapshots are distinct. Category `{id,name,nameMalayalam,kind:'purpose'|'occasion'|'theme',position:number,version:number}`.

- GET `/songs?q=&category=&letter=&featured=true&sort=recent|title&limit=30&offset=0`: public published list.
- GET `/songs/{id}`: public published Song.
- GET `/categories`: `{items:Category[]}`; guests/readers see categories used by published songs, authenticated staff see all categories.
- GET `/config`: `{appName,announcement,aboutText,supportEmail,revision,version}`.
- GET `/events`: SSE `event: content`, `data: {revision:number}`; public invalidation only.
- POST `/auth/register` `{email,password,name}` -> `{message}` (email verification needed).
- POST `/auth/login` `{email,password}` -> `{token,user}`.
- GET `/auth/me` -> User. User `{id,email,name,role:'reader'|'admin'|'owner',verified:boolean,suspended:boolean}`.
- POST `/auth/verify` `{token}`; POST `/auth/forgot-password` `{email}`; POST `/auth/reset-password` `{token,password}`; POST `/auth/logout`; POST `/auth/logout-all`; DELETE `/auth/account` `{password?:string}`. Password accounts require the current password; social-only accounts require a session authenticated within the last ten minutes. Last-owner deletion is rejected. Legacy Apple accounts without a stored grant receive manual revocation guidance after local deletion.
- GET `/auth/challenge` -> `{nonce}` (short-lived, single-use server challenge). POST `/auth/social/{provider}` `{idToken,nonce,authorizationCode?}` -> `{token,user}`; providers google/apple. Backend verifies issuer, audience, nonce and signatures. Link: authenticated POST `/auth/link/{provider}` same input. Linking requires a session authenticated within the last ten minutes. Emails alone never link accounts. Native Google client IDs are configured on mobile; Apple uses expo-apple-authentication and requires its returned authorizationCode. Apple grants are encrypted at rest and revoked during account deletion.
- GET `/auth/providers` -> `{google:boolean,apple:boolean}` (only configured providers visible).
- GET `/me/favorites` -> `{items:string[]}`; PUT `/me/favorites/{id}`; DELETE same path. Idempotent.
- GET `/admin/songs?limit=&offset=&q=` -> draft/current editor versions; GET `/admin/songs/{id}`.
- POST `/admin/songs` -> Song; PUT `/admin/songs/{id}` -> Song (version guard).
- POST `/admin/imports/lyrics` `{entry:{sourceId,sourceUrl,hash,title?,titleMalayalam?,lyricsMalayalam?,lyricsManglish?,credits?,labels?:string[],links?:[{label,url}],reviewNotes?:string[]},dryRun?:boolean}` -> `{total,created,unchanged,conflicts,skipped,review:string[]}` (200). Admin/owner only; one extracted Grejo Lyrics entry per request. `sourceId` must match `tag:blogger.com,1999:blog-6936100729546217639.post-<1–32 digits>`, `sourceUrl` must be a canonical `https://grejolyrics.blogspot.com/YYYY/MM/slug.html` permalink without query/fragment/credentials/port, and `hash` must be 64 hexadecimal characters (normalized lowercase). At least one nonblank title is required; combined lyrics are limited to 200,000 UTF-8 bytes. Empty lyrics produce a skipped report. Credits are limited to 4,000 characters; at most 30 labels (1–120 characters each, trimmed/deduplicated), 30 review notes (1–1,000 characters each), and 10 HTTPS links (1–120-character label, URL at most 2,048 bytes). `RawHTML`, unknown fields, null characters and trailing JSON are rejected. The existing 1 MiB request limit remains. `dryRun` defaults false; true performs no writes. Imports create private drafts only. Repeated source IDs are unchanged when hashes match and conflicts otherwise, always preserving app edits. Draft, categories, first revision, import report and actor audit (`lyrics.import`) commit atomically; failures can be retried safely.
- POST `/admin/songs/{id}/publish` `{version}`; POST `/admin/songs/{id}/unpublish` `{version}`.
- GET `/admin/songs/{id}/revisions` -> `{items:[{id,version,createdAt,content:Song}]}`; POST `/admin/songs/{id}/restore` `{revisionId,version}` -> Song; only the draft changes. Its status still reflects whether an older published snapshot exists.
- POST `/admin/categories` -> Category; PUT `/admin/categories/{id}` with `version` -> Category; DELETE same with `?version=` (unlink safely). Stale writes return409.
- PUT `/admin/config` `{appName,announcement,aboutText,supportEmail,version}` -> config. `version` guards settings edits; `revision` tracks all public content invalidations.
- GET `/admin/users?limit=&offset=` -> `{items:User[],total:number}`; PUT `/admin/users/{id}` `{suspended?:boolean,role?:'reader'|'admin'|'owner'}`. Admins suspend readers only, owner controls admin roles; last owner protected.
- POST `/admin/invitations` `{email}` -> `{message}`; owner only, invitation accepted through POST `/auth/accept-invitation` `{token,password?,name?}`. New accounts require a password; existing accounts must authenticate as the invited identity.
- POST `/analytics` `{event:'song_open'|'category_open'|'search'|'favorite',songId?,categoryId?,resultCount?}` -> 204; optional bearer used to exclude staff, no emails/raw search; client sends when analytics opted in.
- GET `/admin/analytics?days=30` -> `{daily:[{date,event,count}],topSongs:[{id,title,count}],totals:{song_open:number,category_open:number,search:number,no_results:number,favorite:number},mailAlerts?:[]}`.

Identity middleware checks the live session, verification state, suspension and role on every protected operation. Passwords use Argon2id; opaque session credentials are hashed in PostgreSQL. Email and Apple grant payloads use the configured encryption key. The owner/recover-owner CLI commands revoke old sessions and produce audit records.

Migrations in `backend/internal/migrations/*.sql` run once in lexical order under a database advisory lock. Editorial transactions share a lock order to prevent taxonomy removal racing song saves/publication. UUIDs come from PostgreSQL `gen_random_uuid()`.

Importer contract: package importer exposes `Parse(io.Reader) ([]Entry,error)` for Blogger Atom/XML; Entry fields `SourceID, SourceURL, Title, TitleMalayalam,LyricsMalayalam,LyricsManglish,Credits,RawHTML,Hash string; Labels,ReviewNotes []string; Links []Link` and Link `{Label,URL string}`. The application persists entries with unique source ID, skips unchanged/edited source. Importer exposes Fetch(ctx,url) for public paginated feed with same-origin limits. Do not fetch arbitrary URLs supplied by app users.
